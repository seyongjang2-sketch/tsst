# FamilySpace index 단순화 + 수익 흐름 검토

대상 파일: `/mnt/c/Users/Admin/tsst/index.html`
작성 목적: index.html을 직접 수정하지 않고, Apple.com처럼 단순한 섹션 구조로 줄이면서도 내부 클릭, 체류시간, 향후 광고수익 흐름이 죽지 않도록 재구성 방향을 제안한다.

---

## 1. 현재 index 진단

현재 index는 정보량과 시각 장치가 많다. 방문자 입장에서는 “유용한 사이트”라는 느낌은 있지만, 첫 화면에서 무엇을 먼저 눌러야 하는지 판단하기 전에 다음 요소들이 동시에 들어온다.

- 큰 히어로 메시지
- 빠른 길 4개
- 떠다니는 문구 3개
- 칩 6개
- 사이드 카드 2개
- 방문자별 카드 3개
- Family Lab 섹션
- 미션 오빗 인터랙션
- 클릭형 생활 노트
- 체크리스트
- 비교표
- 다음 클릭 루프
- 제작 노트

즉, 수익화 관점의 장점은 이미 많다. 내부 링크, 체크리스트, 비교표, 인터랙션, 신뢰 노트가 있다. 문제는 이 요소들이 한 페이지 안에서 너무 많이 경쟁해서 “한 섹션 한 메시지”가 약해진다는 점이다.

## 2. 검색 방문자/광고수익 관점 질문 답변

### 2.1 누가 검색에서 들어오는가?

가능성이 높은 방문자는 다음 4그룹이다.

1. 베트남 거주 한국인 가족
   - 검색 의도: 베트남 생활비, TRC/비자, 병원, 장보기, 국제결혼 생활 정보

2. 한-베 육아 가족
   - 검색 의도: 아기 식단, 병원, 놀이, 주말 코스, 25개월 루틴

3. 베트남 배우자 또는 가족 구성원
   - 검색 의도: 한국식 육아/식단, 가족 일상, 공감 콘텐츠

4. 중국어권 또는 다국어 방문자
   - 검색 의도: 숫자·표·짧은 비교 중심의 생활 정보

### 2.2 어떤 문제/호기심 때문에 들어오는가?

- “베트남에서 한국 가족이 실제로 한 달에 얼마 쓰나?”
- “TRC/비자 갱신 전에 뭘 준비해야 하나?”
- “베트남에서 아기 병원/식단/마트는 어떻게 고르나?”
- “한-베 가족의 실제 루틴은 어떤가?”

### 2.3 30초, 2분, 5분 체류 이유

- 30초: 첫 화면에서 “생활비 / 아기 / 비자 / 주말” 중 내 상황을 고른다.
- 2분: 선택한 카드에서 짧은 요약, 체크리스트, 비교표를 본다.
- 5분: dad/mom/baby/guide 페이지로 이동해 상세 가이드 또는 표를 읽는다.

### 2.4 내부 클릭은 어디서 발생해야 하는가?

핵심 내부 클릭은 4개만 첫 화면에 남기는 것이 좋다.

- 생활비 → `dad.html` 또는 `guides/krw-vnd-cashflow.html`
- 아기 식단/병원 → `mom.html` 또는 `baby.html`
- TRC/비자 → `guides/trc-visa-checklist.html`
- 가족 일기/루틴 → `blog.html`

### 2.5 스크롤 보상 요소는 무엇이어야 하는가?

장식보다 “내가 저장하고 싶은 것”이 스크롤 보상이 되어야 한다.

- 생활비 미니 비교표
- TRC D-60 체크리스트
- 아기 병원/식단 체크리스트
- 다음에 볼 가이드 3개

### 2.6 광고는 어디에 들어갈 수 있는가?

광고는 첫 화면보다 “유용함을 확인한 뒤” 들어가야 한다.

- 히어로 바로 아래는 비추천: 신뢰와 첫인상을 해친다.
- 첫 번째 실용 카드 묶음 뒤: 가능
- 체크리스트/비교표 아래: 가능
- 관련 글 카드 위 또는 아래: 가능
- 페이지 하단 제작 노트 전: 가능

## 3. 권장 단순 구조: Apple.com식 6섹션

현재 index의 재료를 버리지 말고, 첫 화면 노출 순서를 줄이는 방식이 좋다. 목표는 “한 화면에 한 메시지”다.

### 섹션 1. Hero: 한 문장 + 2개 버튼

메시지:
> 베트남에서 한-베 가족으로 살 때, 오늘 필요한 답부터 찾는 곳.

구성:
- 큰 제목 1개
- 설명 1문단
- CTA 2개만 유지
  - “생활비·비자 가이드 보기”
  - “아기 식단·가족 루틴 보기”

제거/축소:
- 히어로 안의 칩 6개는 삭제 또는 하단으로 이동
- 떠다니는 문구 3개는 제거
- 사이드 카드 2개는 다음 섹션으로 흡수
- 빠른 길 4개는 hero 아래의 독립 카드 섹션으로 이동

수익 흐름:
- 첫 화면은 광고 없이 신뢰 확보
- CTA 클릭률을 높여 내부 페이지 PV 증가

---

### 섹션 2. Quick Path: 4개 카드만

카드 제목:
1. 생활비
   - 링크: `dad.html` 또는 `guides/krw-vnd-cashflow.html`
   - 메시지: 한-베 가족 월간 비용과 송금 루틴

2. 아기
   - 링크: `mom.html` 또는 `baby.html`
   - 메시지: 25개월 식단, 병원, 놀이 루틴

3. 비자/TRC
   - 링크: `guides/trc-visa-checklist.html`
   - 메시지: D-60부터 놓치지 않는 체크리스트

4. 주말
   - 링크: 향후 guide 또는 blog 카테고리
   - 메시지: 카페, 키즈카페, 마트 코스

수익 흐름:
- 첫 내부 클릭의 중심
- 각 카드 아래에 “3분 안에 확인” 같은 짧은 기대 시간을 표시하면 클릭률이 올라간다.

광고 위치:
- 이 섹션 바로 아래에 작은 “관련 가이드 자리” 또는 향후 네이티브 광고 슬롯 가능
- 단, 실제 광고 삽입은 콘텐츠가 충분해진 뒤 권장

---

### 섹션 3. One Useful Thing: 체크리스트 1개만

현재 체크리스트와 비교표를 동시에 보여주기보다, index에서는 하나만 대표로 둔다.

권장 대표 콘텐츠:
> 이번 주 한-베 가족 체크리스트

항목은 4개 유지:
- 아기 병원/약국 위치 저장
- 다음 비자/TRC 날짜 캘린더 입력
- K-Market/WinMart 장보기 비교
- 주말 키즈카페 후보 2곳 선택

수익 흐름:
- 체크박스는 체류시간을 만든다.
- 사용자가 저장하고 싶은 느낌을 주므로 재방문 명분이 생긴다.
- 체크리스트 아래에 `무료 체크리스트 보기` 링크를 두면 guide 페이지로 이동한다.

광고 위치:
- 체크리스트 아래, 다음 섹션 전에 future ad slot 가능
- 문구 예: “관련 생활 가이드 자리”처럼 광고 느낌을 약하게 시작

---

### 섹션 4. Compare: 작은 표 1개

현재 “한국 vs 베트남, 체감 차이” 표는 유지 가치가 높다. 단, 섹션을 크게 단순화한다.

권장 제목:
> 한국 vs 베트남, 가족 생활에서 바로 느끼는 차이

표 항목:
- 아기 외식
- 병원
- 주말 놀이

수익 흐름:
- 표는 스캔하기 쉬워 체류시간과 공유 가능성을 만든다.
- 향후 각 행을 상세 글로 연결할 수 있다.

내부 링크:
- “생활비 전체 표 보기” → `guides/krw-vnd-cashflow.html`
- “아기 병원 체크리스트 보기” → 향후 guide 또는 `baby.html`

### 섹션 5. Next Click: 3개 관련 글/페이지

현재 4개 루프 카드가 좋지만, index 단순화 목적상 3개만 우선 노출한다.

권장 카드:
1. 아빠의 베트남 생존 보드 → `dad.html`
2. 엄마의 식단·힐링 노트 → `mom.html`
3. 아기의 성장 탐험 → `baby.html`

`blog.html`은 하단 텍스트 링크로 낮춰도 된다.

수익 흐름:
- 첫 방문자가 index에서 끝나지 않게 한다.
- 페이지뷰 증가와 광고 노출 가능성을 만든다.

광고 위치:
- 관련 글 카드 위/아래에 네이티브 광고 또는 제휴 링크 영역을 둘 수 있다.

### 섹션 6. Trust Note: 짧은 제작 노트

현재 제작 노트는 좋지만 길다. index에서는 짧게 요약한다.

권장 메시지:
> 이 사이트는 베트남에서 사는 한-베 가족이 실제 생활 속에서 기록한 정보입니다. 비자, 병원, 비용처럼 중요한 결정은 각자 상황에 맞게 다시 확인하세요.

수익 흐름:
- 광고/제휴를 붙이더라도 신뢰 훼손을 줄인다.
- YMYL성 주제(비자, 병원, 비용)에 대한 과장 리스크를 줄인다.

## 5. 광고수익 흐름 설계

### 5.1 index 자체의 역할

index는 광고를 많이 붙이는 페이지가 아니라, “좋은 내부 페이지로 보내는 허브”가 되어야 한다.

이유:
- 검색 방문자가 처음 보는 페이지에서 광고가 많으면 이탈률이 올라간다.
- FamilySpace는 가족/비자/육아/생활비라는 신뢰 기반 주제라 첫 화면 신뢰가 중요하다.
- 실제 광고수익은 상세 guide, dad, mom, baby 페이지에서 더 자연스럽게 발생한다.

### 5.2 추천 광고 슬롯

1. Quick Path 다음
   - 형태: 얇은 네이티브 카드 또는 관련 가이드 추천
   - 목적: 첫 유용성 확인 뒤 자연스러운 노출

2. 체크리스트 아래
   - 형태: “관련 체크리스트/도구” 영역
   - 목적: 체류 후 클릭 유도

3. 비교표 아래
   - 형태: 생활비/보험/송금/마트 관련 제휴 가능 영역
   - 주의: 금융·보험 과장 표현 금지

4. Next Click 섹션 아래
   - 형태: 하단 광고
   - 목적: 페이지를 다 본 방문자 대상

### 5.3 피해야 할 광고 위치

- 히어로 상단
- 언어 선택 바로 옆
- 첫 CTA 버튼 사이
- 체크리스트 항목 사이
- 비자/병원 조언 바로 옆의 과장 광고

## 7. 우선순위 실행안

### 1순위: 첫 화면 단순화

- 히어로 문장 1개
- CTA 2개
- 언어 선택은 작게
- 장식/칩/사이드 정보 축소

효과:
- 사용자가 첫 5초 안에 사이트 목적을 이해한다.
- 내부 클릭 선택지가 줄어 클릭률이 올라간다.

### 2순위: Quick Path 4카드 정리

- 생활비
- 아기
- 비자/TRC
- 주말

효과:
- 광고수익을 만들 상세 페이지로 이동시키는 허브가 된다.

### 3순위: 체류시간 요소 2개만 유지

- 체크리스트
- 비교표

효과:
- 복잡한 인터랙션 없이도 스크롤/체류 이유가 생긴다.

### 4순위: 광고 슬롯은 “미래 자리”로만 표시

- 실제 광고 코드 삽입 금지
- 콘텐츠 흐름을 끊지 않는 위치만 설계

효과:
- 신뢰를 먼저 만들고, 나중에 광고를 붙여도 거부감이 낮다.

## 8. 결론

index.html은 더 단순해져도 수익 흐름이 죽지 않는다. 오히려 현재처럼 많은 요소가 동시에 노출되는 구조보다, `Hero → 4개 선택지 → 체크리스트 → 비교표 → 다음 클릭` 흐름으로 줄이는 편이 내부 클릭과 향후 광고수익에 더 유리하다.

핵심은 index를 “모든 것을 보여주는 페이지”가 아니라 “방문자가 자기 문제를 고르고 상세 페이지로 이동하는 조용한 허브”로 바꾸는 것이다.

권장 최종 방향:

- Apple.com처럼 섹션마다 메시지 하나만 둔다.
- index의 CTA는 2개, Quick Path는 4개로 제한한다.
- 체류시간 장치는 체크리스트와 비교표만 남긴다.
- 광고는 첫 화면이 아니라 유용성을 확인한 뒤의 구간에 둔다.
- 수익은 index 자체보다 dad/mom/baby/guide 상세 페이지의 체류시간과 페이지뷰에서 만든다.
