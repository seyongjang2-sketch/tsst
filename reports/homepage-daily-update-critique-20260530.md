# 홈페이지 매일 업데이트 확장 비판

작성: 2026-05-30 21:55 ICT

## 이번에 고친 것

- `baby.html`, `blog.html`, `stars.html`에 `오늘 실제 반영한 매일 업데이트` 섹션을 추가했다.
- 각 섹션에 `2026-05-30 21:55 ICT` 갱신 시각, 오늘 반영 항목, 이미지 증거를 넣었다.
- Mom/Dad에서 정한 기준인 “날짜/시간 + 실제 항목 + 이미지 증거”를 Baby/Family/Rooftop까지 확장했다.

## 비판

1. 아직 자동 운영이 아니다.
   - 현재는 정적 HTML에 오늘 기준 내용을 박아 넣은 상태다.
   - 내일 같은 문구가 남아 있으면 다시 거짓 운영 표시가 된다.

2. 이미지 증거의 질이 페이지마다 다르다.
   - Mom/Dad는 실제 생활 사진에 가깝다.
   - Baby/Family/Rooftop은 기존 생성 이미지와 층별 이미지를 재사용했다.
   - “오늘 직접 운영했다”는 증거력은 아직 Mom/Dad보다 약하다.

3. Rooftop은 구조상 증거 노출이 약하다.
   - 새 업데이트 카드를 위로 올렸지만, 화면 높이가 낮은 모바일에서는 일부 내용이 접힌다.
   - 옥상 페이지는 3D/HUD UI가 강해서 운영 정보가 보조 요소처럼 보인다.

4. Family Lounge는 Firebase 실데이터와 정적 운영 문구가 분리되어 있다.
   - 실제 일기 피드가 비어 있거나 접근 실패하면 “운영 중” 느낌이 바로 깨진다.
   - 정적 업데이트 카드만으로는 가족 기록이 실제로 쌓이고 있다는 증거가 부족하다.

5. 운영 체계의 핵심 문제는 아직 남아 있다.
   - 매일 업데이트를 사람이 수동으로 HTML에 넣는 방식은 반복 실패 가능성이 높다.
   - 최소한 날짜 만료 경고, 업데이트 데이터 파일, 공개 URL 자동 검증 중 하나는 필요하다.

## 다음 기준

- `daily-updates.json` 같은 단일 데이터 파일을 만들고 각 페이지가 같은 기준을 읽게 해야 한다.
- 날짜가 오늘이 아니면 “매일 업데이트” 문구를 숨기거나 “최근 업데이트”로 낮춰야 한다.
- 공개 URL 검증에는 각 페이지의 날짜 마커와 이미지 파일명을 반드시 포함해야 한다.
- Baby/Family/Rooftop도 실제 생활 사진 또는 해당 페이지 전용 운영 이미지를 추가해야 한다.
